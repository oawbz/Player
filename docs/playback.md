# 播放与生命周期

仅使用 ExoPlayer + FFmpeg 音频扩展。播放页和设置均不提供核心选择。使用 Media3 1.2.1 官方 HTTP 数据源；视频不经过应用资料缓存，也不使用自定义视频 DataSource。

Media3Player 负责 OpenList fs/get 取址、播放、音轨及状态回调。加载和恢复保留转圈，缓冲状态与秒数合并一行，例如“2.00 MB/s · 缓冲中 12 秒”。保留进度、选集和音轨偏好。历史按作品去重，只保留最近 12 部；已有超额记录读取后裁剪并保存。

打开媒体采用独立代次隔离迟到取址结果和播放器回调。退出、进入后台或 Surface 销毁时取消取址、释放实例并保存进度；返回后从保存位置恢复。触屏拖动松手提交一次，遥控器/无障碍进度变化也提交跳转；真正播完后界面与历史保留总时长，直到重播或切集。

点击播放前，ResourceGate 暂停资料队列、取消当前资料请求并等待任务真实退出。分类手动刷新串行运行于同一队列，不创建额外批量线程池。选集目录读取只获取目录，不触发资料下载。

自动测试覆盖地址解析、取消、缓冲计量、资料交接与音轨辅助逻辑；构建和静态检查不替代手机实际解码、前后台、连续切集与遥控器验收。

浏览目录与海报/NFO 共用串行队列，同一页面加载内的相同目录请求合并。首页/分类在配置与记录未变化的 30 秒内返回复用已显示列表；不增加持久目录缓存。历史卡片先进入详情；详情到播放复用两分钟内、同账号且包含当前剧集的一次性选集快照。播放器进程恢复缺少快照时只播放已知视频，不自行列目录，重新进入详情后可恢复完整选集。

自动海报保持内存/磁盘缓存优先，可见稳定 180ms 后读取缺失资料，离屏 250ms 后取消，无人订阅才取消合并请求。缺失/失败冷却 30 秒；429/503 根据 Retry-After 秒数（至少 30 秒、最多一天）暂停自动海报；不轮询重试，手动刷新绕过自动冷却。分类手动刷新复用本次作品列表。

API 和资料下载共用无默认认证的 OkHttp 连接池，移除强制 Connection: close；认证仅在 API 请求添加。取消和超时继续关闭实际请求，视频传输保持现有实现。不记录地址、签名或账号。

统一 minSdk18，使用 Media3 1.2.1 和默认同步解码队列（API23 以上启用异步队列）；官方 FFmpeg 音频扩展使用 NDK r23c，armeabi-v7a 目标 API18、arm64-v8a 目标 API21，FFmpeg 6.0.1。不保留单独现代版或重复 FFmpeg 模块。

详情和列表共享应用内 12 MiB 的缩略图 LRU。海报下载校验时解码出的 480px 缩略图在磁盘原子写入成功后保留并发布；详情只读磁盘缓存时也补齐缺失的列表缩略图。列表直接复用共享 Bitmap。详情 NFO 已有缓存就不再自动下载，海报缺失仍补图。手动刷新成功替换缩略图，失败保留上次成功结果；进程重启或 LRU 淘汰后按磁盘缓存恢复，已有完整磁盘缓存不自动重新下载。

### 有界诊断采样

`-PplaybackDiagnostics=true` 构建开启 `PlaybackProbe`（默认关闭）。每次打开媒体最多采样 180 秒，每秒一条播放器状态、缓冲位置、累计传输字节及音视频解码输入/输出计数，并记录加载开始、结束、取消和错误状态。传输计数按播放器实例累计，打开标记给出基准值；加载任务用数字 ID 对应。释放时注销监听并取消采样。不记录地址、路径、签名、认证或异常文本，不修改取流、缓冲或解码策略。此采样用于排查黑屏却显示长缓冲的异常，不能单凭缓冲秒数宣称已经缓存整部媒体。

0.4.12：视频首帧未到时继续显示“缓冲中”和加载转圈；请求播放且持续等待首帧/缓冲 45 秒后提示手动重试，不自动重连或切换策略。暂停及音频焦点暂失不计入等待；切集、拖动重置计时。尚未输出首帧时不把无画面的时钟推进写入观看进度。播放器选集与详情每页最多显示 24 集；完成的作品从详情重新播放时从零开始。
