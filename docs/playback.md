# 播放与生命周期

仅设置中可选择 MediaPlayer / ExoPlayer，默认 ExoPlayer。选择保存于应用私有配置，错误不会自动换核心。ExoPlayer 使用 Media3 1.8.0 官方 HTTP 数据源与 FFmpeg 音频扩展；MediaPlayer 使用系统网络和解码实现。视频不经过应用资料缓存，也不使用自定义视频 DataSource。

两个核心共用 PlaybackPlayer 接口与 OpenList fs/get 取址。播放页不显示核心名称或切换入口，下次打开播放器时使用设置中的选择。加载、切核和恢复时统一提示“缓冲中”。音轨偏好按核心隔离；现有 ExoPlayer 偏好仍可直接复用。MediaPlayer 不显示无法测量的下载速率。

打开媒体采用独立代次隔离迟到取址结果和播放器回调。退出、进入后台或 Surface 销毁时取消取址、释放实例并保存进度；返回后从保存位置恢复。MediaPlayer 恢复非零进度时等待异步跳转完成，暂停状态不会因此自动播放。

点击播放前，ResourceGate 暂停资料队列、取消当前资料请求并等待任务真实退出。分类手动刷新串行运行于同一队列，不创建额外批量线程池。选集目录读取只获取目录，不触发资料下载。

自动测试覆盖地址解析、取消、缓冲与音轨辅助逻辑，以及 MediaPlayer 准备/跳转/释放后的回调隔离。系统核心测试使用受控媒体回调，不替代手机上的实际解码、连续切核、前后台或遥控器验收。

浏览目录与海报/NFO 共用串行队列，同一页面加载内的相同目录请求合并。首页/分类在配置与记录未变化的 30 秒内返回复用已显示列表；不增加持久目录缓存。详情到播放复用两分钟内、同账号且包含当前剧集的一次性选集快照；恢复入口缺少快照时先读选集，再排空队列并开始视频。

自动海报保持内存/磁盘缓存优先，可见稳定 180ms 后读取缺失资料，离屏 250ms 后取消，无人订阅才取消合并请求。缺失/失败冷却 30 秒；429/503 根据 Retry-After 秒数（至少 30 秒、最多一天）暂停自动海报；不轮询重试，手动刷新绕过自动冷却。分类手动刷新复用本次作品列表。

API 和资料下载共用无默认认证的 OkHttp 连接池，移除强制 Connection: close；认证仅在 API 请求添加。取消和超时继续关闭实际请求，视频传输保持现有实现。播放交接时输出累计请求种类/状态/数量、连接次数、读取字节及耗时，不输出地址、签名或账号。读取字节并非链路流量，静态验证不代表降速问题已解决。

API 18 构建通过 `-Papi18=true` 启用，参照 `/Users/awbz/code/my-tv/app/src/main/java/com/lizongying/mytv/PlayerFragment.kt` 的 MediaPlayer / ExoPlayer 1.2.1 双核组合：系统核心旧版使用 STREAM_MUSIC，旧版 ExoPlayer 使用默认同步解码队列；生命周期保持代次/实例隔离及释放。继续使用官方 HTTP 数据源和本项目 OpenList 取址、点播进度/选集/音轨逻辑，不引入直播源切换与自动重连。此构建使用官方 Media3 1.2.1 FFmpeg 扩展源码与 NDK r23c 单独构建，armeabi-v7a 目标 API18、arm64-v8a 目标 API21，复用 FFmpeg 6.0.1 音频解码器集合；现代默认构建保留 Media3 1.8.0 和 FFmpeg。

详情和列表共享应用内 12 MiB 的缩略图 LRU。海报下载校验时解码出的 480px 缩略图在磁盘原子写入成功后保留并发布；详情只读磁盘缓存时也补齐缺失的列表缩略图。列表绑定卡片即可直接使用共享 Bitmap，不先排队读盘/解码。详情缓存海报/简介完整时不再提交资料刷新。手动刷新成功替换缩略图，失败保留上次成功结果；进程重启或 LRU 淘汰后仍按原有磁盘缓存优先逻辑恢复，已有完整磁盘缓存不自动重新下载。

## 0.4.8 跳转与异常结束

- MediaPlayer 同时只提交一次原生 seek；等待期间的新目标只保留最后一个，旧回调不能解除最新目标的等待状态。每次实际 seek 有 30 秒超时；回调仍偏离目标超过 30 秒时报告失败（保留旧 API 的关键帧跳转余量），保留目标位置供用户点击重试，不自动换核心/重连。
- 结束回调距离总时长仍超过 2 秒时，按意外中断处理，不写成正常播完或归零。错误/超时释放旧实例、隔离迟到回调；真正播完后的界面与历史保留总时长，直到用户重播或切集。
- 触屏拖动松手提交一次；遥控器/无障碍改变进度也提交跳转，程序刷新进度不提交。拖动期间 ticker 不覆盖 SeekBar。
- MediaPlayer 不显示“缓冲中”文字和缓冲秒数，保留加载转圈、播放进度与错误重试提示。系统整文件百分比不能准确表示 Range 跳转后可播放的秒数；ExoPlayer 的速率/缓冲秒数保持不变。
- 数字日志 systemSeek：event=0 提交，1 原生完成，2 结束；只记录目标/实际毫秒数，不含地址、签名或认证。
- 设备对照曾观察到 MediaHTTPConnection unexpected end of stream 随后 NuPlayer EOS；用户确认 ExoPlayer 同一文件正常。这说明现有 MediaPlayer 路径存在异常，但不能据此定位服务端/网络具体原因。上述修复处理应用的跳转竞争和错误分类，尚不能保证底层流中断消失；需要安装后实播验收。
